# Подробный разбор кода «РЕЕСТР»

Этот документ объясняет, как устроена программа и что делает каждый модуль и
каждая значимая функция. Рассчитан на человека, который не писал этот код, но
должен уметь его объяснить.

---

## 1. Общая картина

Программа — это мини-СУБД с терминалом. Пользователь вводит команду, программа
её разбирает, меняет данные в оперативной памяти и показывает ответ.

```text
Пользователь
   │  вводит команду
   ▼
gui.py  (TerminalGUI)
   │  передаёт строку
   ▼
engine.py  (Engine.execute)
   │  выбирает обработчик
   ├── parser.py  — разбирает строку
   ├── models.py  — хранит и проверяет данные
   ├── tutorial.py — проверяет шаги урока
   ├── help_text.py — отдаёт текст справки
   └── render.py — рисует таблицы
   │
   ▼
result.py  (CommandResult)
   │  список строк с типами
   ▼
gui.py  показывает строки разными цветами
```

Главная идея: **интерфейс не хранит данные и не проверяет команды**. Он только
принимает текст и показывает готовый результат. Вся логика — в `Engine` и
`models`. Поэтому логику можно тестировать без окна.

## 2. Запуск программы

### `main.py`

```python
from dbms.gui import run

if __name__ == "__main__":
    run(sys.argv[1:])
```

* импортирует функцию `run` из `dbms/gui.py`;
* передаёт ей аргументы командной строки;
* `sys.argv[1:]` — это всё, что написано после `main.py`. Например,
  `python main.py --demo` передаст `["--demo"]`.

`if __name__ == "__main__"` значит: код выполнится только при прямом запуске
файла, а не при его импорте.

### `run.pyw`

То же самое, но файл с расширением `.pyw` Windows запускает через `pythonw.exe`
— без чёрного окна консоли. Удобно для двойного щелчка.

### `start.bat`

```bat
chcp 65001
cd /d "%~dp0"
start "" pythonw main.py
```

* `chcp 65001` включает UTF-8, чтобы русские буквы не ломались;
* `cd /d "%~dp0"` переходит в папку, где лежит bat-файл;
* `start "" pythonw main.py` запускает приложение без консоли.

## 3. Как проходит одна команда

Пример: `INSERT INTO employees (name, age) VALUES ('Иван', 30)`.

1. GUI забирает строку из `Entry` и вызывает `Engine.execute`.
2. `Engine` убирает `;` в конце и проверяет, не идёт ли урок.
3. `_dispatch` видит, что команда начинается с `INSERT`, и вызывает `_insert`.
4. `_insert` с помощью `parser.py` выделяет:
   * имя таблицы — `employees`;
   * список полей — `name, age`;
   * список значений — `'Иван', 30`.
5. `Table.insert` проверяет:
   * существует ли поле `name`, `age`;
   * нет ли повторов полей;
   * все ли поля заполнены;
   * подходят ли значения по типу.
6. Значения преобразуются: `'Иван'` остаётся строкой, `30` становится `int`.
7. Запись получает следующий `id` и кладётся в словарь `rows`.
8. `Engine` добавляет в `CommandResult` строки «Записал! …».
9. GUI выводит их зелёным и обновляет строку состояния.

Если на любом шаге ошибка, выбрасывается `DBError`. `Engine.execute`
перехватывает её и превращает в две строки: «Ошибка» и «Решение».

## 4. `errors.py` — ошибки с подсказками

```python
class DBError(Exception):
    def __init__(self, message, hint=""):
        self.message = message
        self.hint = hint
```

Это обычное исключение, но с двумя полями:

* `message` — что пошло не так;
* `hint` — как это исправить.

Пример:

```python
raise DBError(
    "Поле «age» ожидает целое число.",
    "Пример: 42 или -7.",
)
```

`Engine` ловит `DBError` и выводит оба текста. Благодаря этому во всей программе
ошибки оформляются одинаково.

## 5. `result.py` — результат команды

```python
@dataclass
class CommandResult:
    lines: list[tuple[str, str]]
    prefill: str | None
    clear_requested: bool
    exit_requested: bool
```

`CommandResult` — это «посылка» от `Engine` к GUI.

* `lines` — список пар `(тип_строки, текст)`. Тип нужен для цвета:
  `success`, `error`, `hint`, `table`, `tutorial` и т.д.
* `prefill` — команда, которую нужно подставить в поле ввода (используется в
  уроке).
* `clear_requested` — просьба очистить экран (команда `CLEAR`).
* `exit_requested` — просьба закрыть приложение (команда `EXIT`).

Методы `add` и `extend` просто добавляют строки. GUI не анализирует текст, а
только смотрит на тип строки и выбирает цвет.

## 6. `human.py` — человеческие фразы

### `greeting()`

Смотрит на текущий час:

* 5–11 — «Доброе утро»;
* 12–17 — «Добрый день»;
* 18–22 — «Добрый вечер»;
* иначе — «Доброй ночи».

Используется в приветствии при запуске и в команде `ПРИВЕТ`.

### `plural(number, one, few, many)`

Выбирает правильную форму русского слова:

```python
plural(1, "запись", "записи", "записей")  # запись
plural(3, "запись", "записи", "записей")  # записи
plural(5, "запись", "записи", "записей")  # записей
```

Учитываются исключения 11–14. Функция используется в строке состояния и
сообщениях, чтобы не было «1 записей».

## 7. `models.py` — хранение данных

Это самый важный модуль. Здесь описано, что такое поле, таблица, база и
менеджер баз.

### 7.1. Константы и проверка имён

* `DATA_TYPES = ("string", "int", "float", "bool")` — допустимые типы.
* `TYPE_ALIASES` — русские и английские синонимы: `строка` → `string`,
  `целое` → `int` и т.д.
* `NAME_RE` — регулярное выражение для имён: буквы, цифры, `_`, первый символ
  не цифра.
* `MAX_NAME_LENGTH = 32`, `MAX_FIELDS = 32` — ограничения.

### `validate_name(raw, kind)`

Проверяет имя базы, таблицы или поля:

1. убирает пробелы по краям;
2. не пустое ли;
3. не длиннее 32 символов;
4. совпадает ли с `NAME_RE`.

Если нет — `DBError` с подсказкой. Возвращает очищенное имя.

### `normalize_type(raw)`

Приводит тип к одному из четырёх:

* `строка`, `str` → `string`;
* `целое`, `integer` → `int`;
* `вещественное`, `double` → `float`;
* `логическое`, `boolean` → `bool`.

Если тип неизвестен — ошибка со списком допустимых.

### `convert_value(raw, field)`

Главная проверка типов. Получает строку от пользователя и поле.

* `string` — возвращает строку как есть;
* `int` — проверяет регуляркой `INT_RE`, затем `int(...)`;
* `float` — допускает точку и запятую, проверяет `FLOAT_RE`, затем
  `float(text.replace(",", "."))`;
* `bool` — принимает `true/false`, `1/0`, `да/нет`, `yes/no`.

При неверном значении — `DBError` с примером. Здесь же видно, почему `1.5` не
подходит для `int`, а `много` — для `float`.

### `format_value(value)`

Готовит значение к выводу:

* `None` → `—` (поле добавлено, но в старой записи не заполнено);
* `bool` → `true` / `false`;
* пустая строка → `''`;
* остальное → `str(value)`.

### `Field`

```python
@dataclass
class Field:
    name: str
    type: str
```

Просто имя и тип. Свойство `label` возвращает `name:type`.

### `Table`

Хранит:

* `name` — имя таблицы;
* `fields` — список `Field`;
* `rows` — словарь `{id: {поле: значение}}`;
* `_next_id` — следующий свободный идентификатор.

Методы:

* `field(name)` — ищет поле без учёта регистра, иначе ошибка.
* `add_field(name, type_name)` — проверяет имя, запрещает `id`, дубликаты и
  превышение лимита, добавляет `Field`.
* `drop_field(name)` — запрещает удалять последнее поле, удаляет поле из
  структуры и из всех записей.
* `insert(pairs)` — принимает список `(поле, значение)`:
  * ищет каждое поле;
  * ловит повтор поля;
  * преобразует значения;
  * проверяет, что заполнены все поля;
  * выдаёт новый `id` и сохраняет запись.
* `get_row(row_id)` — возвращает запись или ошибку с существующими `id`.
* `update(row_id, pairs)` — проверяет запись и поля, преобразует значения,
  обновляет только указанные поля.
* `delete(row_id)` — удаляет запись и возвращает её данные (для сообщения).
* `row_count` — количество записей.
* `snapshot()` — список записей, отсортированный по `id`.

### `Database`

Хранит таблицы в словаре `tables` (ключ — имя в нижнем регистре).

* `table(name)` — найти таблицу или ошибка;
* `create_table(name, definitions)` — сначала создаёт временный `Table`,
  добавляет все поля, и только если всё хорошо, кладёт таблицу в словарь.
  Поэтому при ошибке в поле не появляется «половина» таблицы;
* `drop_table(name)` — удалить;
* `table_names()` — отсортированный список;
* `row_count` — сумма записей по всем таблицам.

### `DatabaseManager`

Хранит все базы и имя текущей.

* `create_database(name)` — проверяет уникальность без учёта регистра,
  создаёт базу. Если это первая база, делает её текущей.
* `database(name)` — найти базу или ошибка.
* `use(name)` — сделать текущей.
* `drop_database(name)` — удалить; если она была текущей, сбросить указатель.
* `current_database()` — вернуть текущую или `None`.
* `require_database()` — вернуть текущую или ошибка «Сначала выберите базу».
* `database_names()` — список для `SHOW DATABASES`.
* `reset()` — полностью очистить память.

## 8. `parser.py` — разбор строк

Обычное деление строки по запятым ломается на значениях вроде
`'Иванов, Иван'`. Поэтому написан собственный разбор.

### `split_top_level(text, separator=",")`

Идёт по строке посимвольно и запоминает:

* `quote` — находимся ли внутри кавычек;
* `depth` — глубину скобок.

Делит только там, где `depth == 0` и нет кавычек. Поддерживает `\'` внутри
строки. Если кавычка или скобка не закрыта — `DBError`.

Пример:

```text
"name, 'Иванов, Иван', age"
→ ["name", "'Иванов, Иван'", "age"]
```

### `find_keyword(text, keyword)`

Ищет `SET` или `WHERE` вне кавычек и скобок. Проверяет границы слова, чтобы
`SETTING` не считался за `SET`.

### `extract_parenthesized(text, start)`

Находит `(`, идёт до парной `)` с учётом кавычек и вложенных скобок. Возвращает
содержимое и позицию после `)`.

Используется в `CREATE TABLE`, `INSERT ... VALUES (...)`.

### `parse_literal(token)`

Убирает обрамляющие кавычки:

```text
"'Иван Петров'" → "Иван Петров"
```

Обрабатывает `\'` и `\\`. Если кавычек нет — возвращает строку как есть.

### `split_assignment(text)`

Делит `поле = значение` по первому `=` вне кавычек. Нужен для `UPDATE ... SET
salary = 60000, email = '...'`.

## 9. `render.py` — рисование таблиц

### `render_table(table, rows)`

Собирает заголовки:

```text
id | name (string) | age (int)
```

и строки значений. Затем вызывает `render_matrix`.

### `render_matrix(headers, rows)`

1. Обрезает слишком длинные ячейки (`MAX_CELL = 36`).
2. Считает ширину каждой колонки.
3. Рисует границы `+---+`.
4. Выравнивает текст через `ljust`.
5. Возвращает список готовых строк.

Это чисто оформление: данные не меняются, обрезается только вывод.

## 10. `help_text.py` — тексты справки

Здесь нет логики — только списки строк.

## 11. `engine.py` — мозг программы

### `Engine.execute(raw)`

Главный метод. Что делает:

1. Убирает пробелы и `;` в конце.
2. Если строка пустая — возвращает пустой результат.
3. Определяет, является ли команда служебной для урока.
4. Если урок активен и команда не та — возвращает подсказку, не выполняя её.
5. Вызывает `_dispatch`.
6. Ловит `DBError`:
   * «Ошибка: …»;
   * «Решение: …»;
   * «Не переживайте: данные не пострадали».
7. Ловит любые другие исключения, чтобы приложение не падало.
8. Если урок активен, передаёт команду в `tutorial.after_command`.
9. Возвращает `CommandResult`.

### `Engine.status_line()`

Короткая строка для нижней панели GUI. Использует `plural`:

```text
Сейчас: база «demo» · 1 таблица · 3 записи
```

### `Engine._dispatch(command, result)`

Это «развилка». Сначала служебные команды:

* `EXIT`, `QUIT`, `ВЫХОД`, `ПОКА` — попросить GUI закрыться;
* `CLEAR`, `CLS`, `ОЧИСТИТЬ` — попросить очистить экран;
* `ПРИВЕТ`, `ЗДРАВСТВУЙ`, `HELLO` — `_hello`;
* `СПАСИБО` — ответ;
* `КАК ДЕЛА` — ответ;
* `HELP` / `ПОМОЩЬ` — `_help`;
* `ABOUT` — `_about`;
* `STATUS` — `_status`;
* `DEMO` — `_demo`;
* `TUTORIAL` — `_tutorial`.

Затем базы:

* `CREATE DATABASE` — создать;
* `SHOW DATABASES` — показать;
* `USE` — выбрать;
* `DROP DATABASE` — удалить с `CONFIRM`.

Затем таблицы:

* `CREATE TABLE`;
* `SHOW TABLES`;
* `DESCRIBE`;
* `ALTER TABLE ADD/DROP`;
* `DROP TABLE`.

Затем данные:

* `INSERT`;
* `SELECT`;
* `UPDATE`;
* `DELETE`.

Если ничего не совпало — ошибка «Команда не распознана» с советом `HELP`.

### Обработчики баз и таблиц

* `_show_databases` — список баз, отмечает текущую `*`, пишет количество таблиц
  и записей.
* `_show_tables` — список таблиц текущей базы.
* `_create_table` — извлекает скобки, делит поля, проверяет формат `имя:тип`,
  вызывает `Database.create_table`.
* `_describe` — выводит матрицу «поле / тип / примечание» и количество записей.
* `_alter_table` — `ADD` разбирает `поле:тип`; `DROP` удаляет поле.

### Обработчики данных

* `_insert`:
  * поддерживает `INSERT INTO t (поля) VALUES (значения)`;
  * поддерживает `INSERT INTO t VALUES (значения)` — по порядку полей;
  * проверяет количество полей и значений;
  * вызывает `Table.insert`.
* `_select`:
  * `SELECT * FROM t` — все записи;
  * `SELECT * FROM t WHERE id = N` — одна;
  * короткая форма `SELECT t`;
  * рисует таблицу через `render_table`.
* `_update`:
  * находит `SET` и `WHERE`;
  * требует `WHERE id = N`;
  * делит присваивания по запятым;
  * вызывает `Table.update`.
* `_delete`:
  * требует `WHERE id = N`;
  * вызывает `Table.delete`;
  * показывает удалённые данные.

### `_demo`

Создаёт базу `demo`, таблицу `registry` и три записи, если их ещё нет.
Переключается на `demo` и показывает таблицу.

### `_hello`, `_status`, `_about`

* `_hello` — приветствие по времени суток и три предложения: `TUTORIAL`,
  `DEMO`, `HELP`.
* `_status` — текущая база, количество таблиц/записей и состояние урока.
* `_about` — краткое описание программы.

### `_help`

Просто передаёт раздел в `build_help` и добавляет строки в результат.

### Вспомогательные методы

* `_parse_confirmation(rest)` — проверяет, заканчивается ли команда словом
  `CONFIRM`; возвращает имя и флаг.
* `_ensure_end(text, position, block)` — проверяет, что после скобок нет
  лишнего текста.

## 12. `tutorial.py` — интерактивный урок

### `Step`

```python
@dataclass
class Step:
    title: str
    task: str
    example: str
    pattern: re.Pattern
    check: Callable
    hint: str
```

* `title` — название шага;
* `task` — что нужно сделать;
* `example` — готовая команда, которая подставляется в поле ввода;
* `pattern` — регулярка, какая команда допустима на шаге;
* `check` — функция, проверяющая реальное состояние данных;
* `hint` — подсказка при ошибке.

### Вспомогательные проверки

* `_db()` — найти учебную базу;
* `_table()` — найти таблицу `employees`;
* `_check_fields()` — проверить, что поля именно `name/age/salary/active` и
  нужных типов;
* `_check_email()` — проверить, что добавлено поле `email:string`.

### `_build_steps()`

Создаёт 13 шагов:

1. `CREATE DATABASE tutorial_db`;
2. `USE tutorial_db`;
3. `CREATE TABLE employees (...)`; 
4. `DESCRIBE employees`;
5. `ALTER TABLE employees ADD email:string`;
6. `INSERT` первого сотрудника;
7. `INSERT` второго;
8. `SELECT * FROM employees`;
9. `UPDATE ... salary = 60000, email = ... WHERE id = 1`;
10. `DELETE FROM employees WHERE id = 2`;
11. финальный `SELECT`;
12. `DROP TABLE employees CONFIRM`;
13. `DROP DATABASE tutorial_db CONFIRM`.

### Управление

* `start()` — удаляет старую учебную базу, обнуляет индекс, печатает
  приветствие и первый шаг. Возвращает `prefill` — команду для поля ввода.
* `stop(completed)` — выключает урок; при завершении хвалит пользователя.
* `restart()` — `start()` заново.
* `status()` — текущий шаг.
* `is_control(raw)` — разрешает `TUTORIAL`, `HELP`, `CLEAR`, `STATUS`,
  `ABOUT` на любом шаге.
* `matches_current(raw)` — подходит ли команда под шаблон текущего шага.
* `blocked_result()` — сообщение «давайте сначала закончим шаг».
* `after_command(raw)` — проверяет `step.check()`:
  * не выполнено — подсказка;
  * выполнено — следующий шаг;
  * шагов больше нет — `stop(completed=True)`.
* `_step_lines()` — оформление шага: номер, задание, команда, подсказка.

Важно: урок проверяет **фактическое состояние данных**, а не только текст
команды. Поэтому нельзя «обмануть» урок, введя правильную команду с неверными
данными.

## 13. `gui.py` — окно программы

### Константы

В начале файла заданы цвета (`BG`, `ACCENT`, `GREEN`, `RED` и т.д.) и шрифты.
Менять внешний вид удобно в одном месте.

### `TerminalGUI.__init__`

* создаёт `Engine`;
* задаёт заголовок;
* подстраивает размер окна под экран;
* вызывает `_build_menu`, `_build_header`, `_build_output`, `_build_input`,
  `_build_status`;
* печатает приветствие;
* ставит курсор в поле ввода.

### `_build_menu`

Меню «Файл», «Инструменты», «Справка». Пункты вызывают те же команды, что и
ручной ввод (`_run("DEMO")` и т.д.).

### `_build_header`

Заголовок «РЕЕСТР», подзаголовок и кнопки «Обучение», «Команды», «Демо»,
«Очистить».

### `_build_output`

Создаёт `tk.Text` только для чтения, вертикальную и горизонтальную прокрутку,
теги цветов:

* `success` — зелёный;
* `error` — красный;
* `hint` — жёлтый;
* `table` — светлый;
* `tutorial` — фиолетовый;
* `banner` — голубой.

Также добавляет контекстное меню «Копировать / Выделить всё».

### `_build_input`

Строка ввода `❯`, кнопка «Выполнить», подсказка по клавишам. Привязки:

* `Enter` — выполнить;
* `↑`/`↓` — история;
* `Tab` — автодополнение;
* `Ctrl+L` — очистить;
* `F1` — справка.

### `_build_status`

Нижняя панель: зелёная точка, `status_var` из `Engine.status_line()` и надпись
«Данные только в памяти».

### `_print_banner`

Печатает приветствие по времени суток, объясняет, что данные в памяти, и
предлагает `HELP` / `TUTORIAL` / `DEMO`.

### `append`, `_clear_screen`, `_copy_selection`, `_select_all`

* `append` — добавляет строку в Text с нужным тегом и прокручивает вниз.
* `_clear_screen` — очищает вывод.
* `_copy_selection` / `_select_all` — работают с буфером обмена.

### `submit`

Главный обработчик ввода:

1. берёт строку;
2. очищает поле;
3. запоминает команду в истории;
4. печатает `❯ команда`;
5. вызывает `engine.execute`;
6. если нужно — очищает экран;
7. выводит все строки результата с их цветами;
8. подставляет `prefill`, если урок просит;
9. обновляет статус;
10. если `exit_requested` — закрывает окно.

### `_run`

Выполняет команду из меню/кнопки: подставляет текст в поле и вызывает `submit`.

### История и автодополнение

* `_remember` — не добавляет дубликаты подряд;
* `_history_up/down` — листают историю;
* `_complete` — по `Tab` подставляет первую подходящую команду из списка.

### `_reset_data`, `_about`, `on_close`

* сброс данных с подтверждением;
* окно «О программе»;
* выход с предупреждением, что данные в памяти.

### `run(initial_commands)`

* включает DPI-awareness, чтобы окно не было размытым;
* создаёт `Tk` и `TerminalGUI`;
* если переданы команды (`--demo`, `--tutorial` или свои), выполняет их через
  `root.after` с задержкой;
* запускает `mainloop`.

## 16. Как хранятся данные: пример

После команд:

```text
CREATE DATABASE demo
CREATE TABLE employees (name:string, age:int, salary:float, active:bool)
INSERT INTO employees (...) VALUES ('Иван', 30, 55000.5, true)
```

в памяти лежит примерно так:

```python
DatabaseManager(
    current="demo",
    databases={
        "demo": Database(
            name="demo",
            tables={
                "employees": Table(
                    name="employees",
                    fields=[
                        Field("name", "string"),
                        Field("age", "int"),
                        Field("salary", "float"),
                        Field("active", "bool"),
                    ],
                    rows={
                        1: {
                            "name": "Иван",
                            "age": 30,
                            "salary": 55000.5,
                            "active": True,
                        }
                    },
                    _next_id=2,
                )
            },
        )
    },
)
```

Никаких файлов и SQL-сервера нет. Поэтому после закрытия всё исчезает.

## 17. Обработка ошибок: пример

```text
INSERT INTO employees (name, salary) VALUES ('Иван', 'мало')
```

1. `_insert` разбирает поля и значения.
2. `Table.insert` вызывает `convert_value('мало', salary:float)`.
3. `FLOAT_RE` не совпадает → `DBError`.
4. `Engine.execute` ловит ошибку.
5. GUI получает три строки:

```text
Ошибка: Поле «salary» ожидает число (float), получено «мало».
Решение: Пример: 55000.50 или 12,5. Можно использовать точку или запятую.
Не переживайте: данные не пострадали. Если нужно, HELP подскажет.
```

Данные не меняются, потому что проверка идёт до `rows[id] = values`.

## 18. Почему это СУБД, хотя и учебная

Есть все базовые признаки:

* базы → таблицы → поля → записи;
* уникальные имена;
* типы данных и проверка;
* автоматический `id`;
* CRUD-операции;
* ошибки и ограничения.

Отличия от «взрослой» СУБД: нет файлов, транзакций, внешних ключей, SQL-джойнов
и сетевого режима. Это осознанные ограничения задания.

## 19. Как объяснить проект за минуту

> «Пользователь пишет команду в окно. GUI передаёт её в Engine. Engine
> разбирает строку, вызывает модель данных и возвращает готовые строки.
> Модель хранит базы, таблицы и записи в словарях Python в оперативной памяти.
> Если что-то не так, программа не падает, а показывает ошибку и решение.
> Есть урок из 13 шагов и 42 автоматических теста».
