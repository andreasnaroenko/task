# Как объяснить проект простыми словами

Эта памятка — для защиты и ответов на вопросы. Здесь нет сложных терминов:
только суть проекта и то, как работает программа.

---

## 1. Одна фраза о проекте

«РЕЕСТР» — это программа, которая работает как маленькая база данных:
пользователь пишет команду в окно терминала, а программа создаёт базы,
таблицы и записи и хранит их в оперативной памяти.

---

## 2. Из чего состоит программа

Можно запомнить четыре уровня:

```text
Пользователь
    ↓ вводит команду
GUI-терминал (gui.py)
    ↓ передаёт строку
Исполнитель (engine.py)
    ↓ вызывает
Модель данных (models.py)
    ↓ возвращает результат
GUI-терминал показывает ответ
```

Простыми словами:

1. **GUI** — окно, поле ввода и вывод. Он ничего не решает, только
   показывает.
2. **Engine** — «диспетчер». Понимает команду и решает, что делать.
3. **Models** — «хранилище». Там лежат базы, таблицы, поля и записи.
4. **Parser** — «помощник», который правильно делит строку на части, если
   внутри есть кавычки, запятые или скобки.

---

## 3. Какие файлы достаточно знать

| Файл | Простыми словами |
|---|---|
| `main.py` | запускает программу |
| `dbms/gui.py` | окно терминала |
| `dbms/engine.py` | выполняет команды |
| `dbms/models.py` | хранит данные |
| `dbms/parser.py` | разбирает строку команды |
| `dbms/tutorial.py` | интерактивный урок |
| `dbms/help_text.py` | тексты справки |
| `dbms/render.py` | рисует таблицы символами |
| `tests/test_engine.py` | автоматические проверки |

Остальные файлы — вспомогательные: `errors.py` хранит ошибку с подсказкой,
`result.py` — результат команды, `__init__.py` — описание пакета.

---

## 4. Что происходит, когда пользователь вводит команду

Пример: `CREATE TABLE employees (name:string, age:int)`.

1. GUI забирает текст из поля ввода и передаёт его в `Engine`.
2. `Engine` смотрит первое слово — `CREATE` — и понимает, что это таблица.
3. `Parser` аккуратно выделяет имя таблицы и список полей.
4. `Engine` проверяет, выбрана ли база, нет ли такой таблицы и полей.
5. `Database` создаёт таблицу, `Table` добавляет поля.
6. `Engine` собирает ответ: «Таблица создана».
7. GUI показывает ответ зелёным цветом.

Если что-то не так, программа не падает, а пишет:

```text
Ошибка: Таблица «employees» уже существует.
Решение: Придумайте другое имя или удалите её: DROP TABLE employees CONFIRM.
```

## 5. Как хранятся данные

Очень просто:

```text
DatabaseManager
  └── Database («demo»)
        └── Table («employees»)
              ├── Field («name», string)
              ├── Field («age», int)
              └── rows: {1: {...}, 2: {...}}
```

* **DatabaseManager** знает все базы и какая база сейчас выбрана.
* **Database** хранит таблицы.
* **Table** хранит поля и записи.
* **Field** — это просто имя и тип.
* **Запись** — словарь «поле → значение» плюс автоматический `id`.

Всё лежит в обычных словарях Python. Поэтому программа не требует SQL-сервера
и работает в изолированной среде.

---

## 6. Почему это можно назвать СУБД

Потому что есть основные признаки базы данных:

* данные организованы в базы, таблицы, поля и записи;
* у записей есть уникальный идентификатор;
* типы значений проверяются;
* есть команды создания, чтения, изменения и удаления;
* есть защита от дубликатов и ошибок ввода.

Это учебная СУБД: она проще настоящей, но показывает те же принципы.

## 8. Как показать работу за 2 минуты

1. Запустить `python main.py`.
2. Ввести `DEMO` — появится готовая таблица сотрудников.
3. Ввести `DESCRIBE registry` — показать структуру.
4. Ввести `UPDATE registry SET salary = 70000 WHERE id = 1` — показать
   изменение.
5. Ввести `SELECT * FROM registry WHERE id = 1` — показать результат.
6. Ввести заведомо неверную команду, например
   `INSERT INTO registry (salary) VALUES ('мало')` — показать ошибку и
   строку «Решение».
7. Ввести `TUTORIAL` — показать обучение.

## 9. Ответы на простые вопросы

**Где хранятся данные?**
В оперативной памяти, в словарях Python. После закрытия программы они
исчезают — так требует задание.

**Почему нет файла базы данных?**
Потому что запрещено использовать сторонние СУБД и требуется хранение в RAM.

**Почему команды похожи на SQL?**
Так пользователю привычнее. Но это не настоящий SQL, а собственный простой
язык команд.

**Что будет, если ввести ерунду?**
Программа покажет ошибку и подсказку, но не закроется. Это проверено тестами.

**Почему запись меняется только по id?**
Чтобы нельзя было случайно изменить сразу всю таблицу.

**Можно ли добавить поле в готовую таблицу?**
Да: `ALTER TABLE employees ADD email:string`. У старых записей оно будет
показано как «—».

**Где в коде проверяются типы?**
В `models.py`, функция `convert_value()`.

**Где в коде обрабатываются ошибки?**
Ошибка создаётся в `errors.py`, перехватывается в `engine.py`, а текст
подсказки выводится в GUI.

**Как проверяли программу?**
42 теста в `tests/test_engine.py` и ручные сценарии из инструкции.
